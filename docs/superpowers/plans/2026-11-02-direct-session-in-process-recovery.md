**Goal:** Let the exact bound parent retire a stopped foreground direct implementation only after retained operation, callback, authority and native termination proof, then admit a completely fresh orchestration.

## Global Constraints

- Default-off Linux V2 fresh foreground `implementer/implementation` remains the only direct route. Preserve exactly four active role names: `researcher`, `planner`, `implementer`, and `validator`.
- Initial typed stop allowlist is exactly `deadline-expired` and `caller-cancelled`, minted only by the admitted deadline check/timer or exact captured caller AbortSignal. Equal strings, copied objects, generic catches and model input cannot establish provenance.
- The original task deadline, budgets, gates and stopped status remain unchanged. Default budgets remain `{"mode":"unbounded"}`; retain bounded numeric specifications. Existing task timeout default is 300,000 ms, maximum 3,600,000 ms; introduce no new lifetime/resource cap.
- Recovery observation budget is 2,000 ms for the entire fresh sequence, using a separate monotonic deadline per explicit resolve/release observation. This is trusted construction/test state, never a tool argument.
- Context remains bounded after allocation at 256 messages/1,048,576 bytes; retain the existing 32,768-character successful-result limit and existing 4096 owned-attempt bound. Native idle never drains an operation or callback ledger.
- Require invoked, fulfilled, exactly acknowledged create and prompt, correlated creation event, and the exact own promoted prompt. No-create/no-prompt, rejected/malformed native operations, missing child, queued/unobserved prompt and missing native after stay blocked.
- An initial allowed stop does not excuse a later independent fault. Event loss/reconnection, unload/dispose, authority/identity/scope/artifact/proof-processing faults and unclassified stops are sticky disqualifiers. Same private stop propagation alone is idempotent.
- Stopped candidates/results/gates never become accepted. New orchestration/spec, delegation task, call, child and prompt identities are mandatory after release. Keep old children terminal and old controllers interrupted; re-establish gates with independent validators.
- Public recovery tools/arguments, launcher flags, activation marker shape, role/permission policy, native result schema, package dependencies and Job recovery behavior do not change. Release remains capped at four per plugin process.
- Same live plugin instance, exact bound parent and exact owned version-1 lease only. No lease adoption, durable journal, generic reload recovery, native core patch, validator route, compaction, child deletion, inbox mutation, background replay or model-supplied receipt/lease/timeout.
- No native/provider/auth/network/global installation/publication. Offline fixtures use fake APIs/binaries in private owner-controlled roots. A source audit proves committed-source seams, not live activation or managed gate acceptance.
- Native source authority is committed Git blobs at `68bc26b7da1990ce10ffecfbc1e09eb13aa5d824` in `/home/joshl/.cache/opencode-harness/v2-native-api-src`; its dirty working tree is not evidence.
- Source/portable/external closures remain independent; portable validation depends only on its manifest and seeded memory. Keep existing production modules and the 73-file package closure unless a necessary new production module is separately justified and all inventories are updated together.
- Global runtime source/generated adapter code, manifest membership, import closure and capabilities remain unchanged. Shared bootstrap protocol documentation may change while retaining its explicit global-native exclusion.

## Review Focus

1. Native cancellation can bypass error after-hooks: the fixture must exercise actual cancellation semantics and leave a missing after blocked (Task 2).
2. A body `finally` can finish while its returned Promise or a subsequent reaction is still outstanding: resolve/release must block until the actual owned returned Promise settles (Tasks 1–2).
3. Late prompt admission/wake or a synchronous native callback can run after an earlier idle observation: register before invocation, drain all original continuations, then perform fresh interrupt/wait (Task 1).
4. Same-byte marker/root/lease replacement or a late callback after `active` clears can invalidate previously reviewed proof: retain exact identity/generation and refuse release (Task 2).
5. Lease removal can fail after unlink: keep the in-memory stop and give truthful exact-path present/missing/unknown diagnostics without claiming durability (Task 2).
