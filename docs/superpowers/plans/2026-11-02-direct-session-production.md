# Direct Session Production Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development with fresh implementation and independent review tasks. The owner already selected this method and authorized this tranche in the current checkout; preserve that authorization. Steps use checkbox tracking.

**Goal:** Ship an explicit, default-off V2 implementation-task transport with safe local artifact rejection and fresh managed remediation.

**Architecture:** Wrap the existing native subagent executor only for an admitted fresh foreground implementation task. A private receipt is finalized in its matching native after-hook; the existing managed controller owns all attempts, deadlines, scope and proof. One fixed owner-only trace-wide unresolved lease blocks unsafe reload and rollback without scanning or limiting completed orchestration history.

**Tech Stack:** Node 24, authored TypeScript, generated dependency-free JavaScript, built-in node:test, existing controller/contracts/proof modules.

**Spec:** `docs/superpowers/specs/2026-11-02-direct-session-production-design.md`.

## Global Constraints

- Exactly four roles; direct transport supports only fresh foreground `implementer/implementation` without explicit model override. All other role/mode/background mappings retain guarded native dispatch.
- One direct attempt per parent native call; remediation requires a fresh call, task, child and prompt. Default budgets remain `{"mode":"unbounded"}`; bounded numeric specifications remain bounded.
- Fixed admitted deadline, trusted maximum 3,600,000 ms, default 300,000 ms; 2,000 ms reconciliation never renews it. Local post-read limits: 256 messages, 1,048,576 bytes, existing 32,768-character terminal result.
- No native core changes, Job/synthetic path for direct attempts, global-native changes, runtime TypeScript dependency, live activation/provider/auth/network/global installation/publication.
- Native API audit reads committed blobs at `68bc26b7da1990ce10ffecfbc1e09eb13aa5d824`, never the reference worktree.
- Opt-in is `--v2-direct-implementation` on `run`/`source-tui`; absence is off. Unresolved leases block both settings and cannot be manually deleted as recovery.

## Review Focus

1. Native `execute.after` delayed beyond wait or omitted entirely: reservation and lease must remain until the exact own callback is accounted for.
2. Crash between persisted lease and create acknowledgment: restarted/direct-off setup must retain refusal, even under a new orchestration ID.
3. Another prompt or child creation races final proof: stop, suppress all result channels, and retain capacity.
4. Artifact-proof rejection is narrower than unsafe scope/identity/native failure: only the former permits a fresh managed attempt.
5. Profile activation advertises old guard metadata or misses a module: no client attaches and no external fallback replaces a damaged portable guard.
