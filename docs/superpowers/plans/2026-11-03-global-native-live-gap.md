# Global-native continuation evaluation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Provide an operational source-only plugin that records bounded, exact-child continuation cancellation and native late-result rejection observations without changing the shipping adapter.

**Architecture:** Register exactly one existing global adapter through a context proxy. Observe its real registered hooks, capture verified clarification completions, and add source-only arm/status controls plus an exact-token read-only rendezvous tool. Hold selected native after callbacks outside the adapter's serial queue; cancellation always calls the actual registered `harness_orchestration` executor.

**Tech Stack:** Node 24, TypeScript/MTS, Node test runner, pinned OpenCode Promise plugin API.

**Spec:** `docs/superpowers/specs/2026-11-03-global-native-live-gap-design.md`.

**Approval and execution:** The owner approved continuation-first implementation and validation on November 3, 2026 and selected fresh implementation agents with independent review. That authorization supersedes the older proposal/pending language still present in the design and runbook. This plan is ready for execution; do not request another approval. Work is under the explicitly approved Codex direct bootstrap exception, outside managed acceptance. Live provider/network/native activation is not authorized by this implementation instruction.

## Global Constraints

- Keep shipping global adapter behavior unchanged for the first closure attempt.
- Source evaluator arms accept researcher/research only; unsupported roles/modes refuse without attempt/protocol mutation. Native four-role orchestration is unchanged.
- `GN-010-FRESH remains NOT_EXERCISED`.
- Cancellation returns `termination: "unconfirmed"`; it does not interrupt native execution.
- No production release mechanism or protocol bypass is added.
- No provider, network, auth, global installation, native database reuse or host activation during implementation/QA.
- Source-only evaluation code stays outside installed assets, manifest/package closures and ordinary startup. Source inventory is distinct from release manifests.
- A completion already held before cancellation cannot prove GN-010.
- Timeouts, aborts, identity changes, unavailable events and disposal are INCONCLUSIVE; they never release protocol reservations, retire uncertain runs, renew deadlines or restore acceptance gates.
- Both control versions 1 and 2 need separate attempts and raw/text JSON checks. Offline modeled callbacks remain FIXTURE; no offline success closes LIVE cases or manual T3Code coverage.

## Review Focus

- A delayed old event on the verified child must not satisfy a fresh continuation boundary; require exact parent/message/call mapping and a never-before-used rendezvous token.
- A second plugin or inherited project/global configuration must prevent a live evaluation setup; the source driver must instantiate only one adapter and inspect native plugin/tool availability.
- Abort/timeout/disposal during native lookup, cancellation or an after hold must settle owned Promises and subscriptions without claiming the protocol is released.
- Rich native content, undefined raw fields or mismatched metadata must not be hidden by JSON serialization; retain raw output, content and metadata separately.
- A direct `subagent.execute` or `/delegate-*` dispatch does not establish core-dispatched after provenance; the operational attempt uses the parent's normal native subagent tool path.

**Produced interfaces in `global-native-live-eval.mts`:**

- `createGlobalNativeLiveEval(ctx: EvalNativeContext, options: {timeoutMs?:number; traceRoot:string; now?:()=>number}): Promise<{arm(request: EvalArmRequest, parentSessionID:string):Promise<EvalSnapshot>; snapshot():EvalSnapshot; dispose():Promise<void>}>`.
- `EvalNativeContext` adds the pinned public event subscription, registration disposal, native full tool context, `plugin.list()` inspection and `location.directory` to the existing adapter's structural context. Declare the structural subset locally; do not enlarge shipping adapter interfaces for a test tool.
- `EvalArmRequest = {mode:"continuation-rendezvous"|"completed-after-hold"; controlVersion:1|2; context:TaskContext; childSessionID:string; requestNonce:string}`. Derive generation/parent agent/cwd/original deadline and verified clarification call from observed adapter admission/result state, not arm input. Reject missing/mismatched context or another active attempt. Arm one selected task only; default timeout 15000 ms, valid integer range 1..60000, never beyond original task deadline.
- `EvalSnapshot` is a plain JSON-safe observation record containing attempt ID, mode, phase, diagnostic outcome (`PENDING|OBSERVED|INCONCLUSIVE`), original identities/deadline, bounded ordered observations, cancellation raw output/text, callback before/release hashes, resulting raw output/content/metadata and missing surfaces. Never report universal LIVE PASS. Cap observations at 256 and retained individual payloads at 64 KiB; overflow makes INCONCLUSIVE, no silent truncation or success. Keep data in memory; no automatic evidence writes by the child/driver.
- Default export ID `opencode-harness.source-global-live-eval.v1`; setup requires explicit isolated-root/trace-root plugin options and required API capabilities, rejects duplicate adapter ownership, installs one driver, returns its cleanup. Register `harness_eval_control` with `arm` and `status` actions (parent-only native identity) and `harness_eval_rendezvous` with `{attemptID,token}` (child-only native identity). Both use strict JSON schemas, `codemode:false`, JSON-safe output plus matching JSON text. Arm returns the fresh token and exact continuation response prompt for the operator/parent to dispatch through ordinary native `subagent`.
