# Global-native verified cancellation and late-result design

Status: **PROPOSED — owner design review pending**. This is a source-only design, not an implementation plan or completed evaluation. No implementation or live tests were run for this proposal. GN-010 and GN-011 remain **NOT_EXERCISED**.

## Intent and evidence boundary

Close the two remaining [global-native regression cases](../../global-native-regression-evals.md): GN-010 needs trustworthy evidence that an exactly correlated native child is executing before protocol cancellation; GN-011 needs a genuine native completion delivered after cancellation and rejected on actual native output surfaces. A pending callback, a candidate session ID, the adapter's `running` label, silence after Stop, or modeled callback fixtures do not establish those claims.

The existing adapter learns a fresh child only in completed `execute.after`. Cancellation changes protocol state and returns `termination: "unconfirmed"`; it does not interrupt native execution. Retain that meaning. This proposal uses existing verified-child continuation and source-only evaluation control; it does not add a production native abort/termination guarantee, new acceptance gates, a durable recovery mechanism, or legacy guard imports.

Read-only capability research used committed native Git blobs at `68bc26b7da1990ce10ffecfbc1e09eb13aa5d824`, not its working tree. The recorded source adapter baseline was `ffadcca`. Findings are specific to that pinned API; a different native build needs compatibility proof before live use.

## Verified public capability and trust boundary

The pinned Promise plugin context exposes `event`; `ctx.event.subscribe({signal})` yields an async iterable of public events with `type` and `data`. Native subagent emits `context.progress({sessionID: child.id, status: "running"})` before prompting. The public `session.tool.progress` event carries the parent `sessionID`, `assistantMessageID`, exact call `id`, and metadata. That supplies an exact originating-call mapping, whereas `session.created` has no originating call ID. Native `session.execution.started` carries the child session ID and can supply separate execution-start evidence after identity correlation. Keep those observations distinct: progress announces launch before prompt and cannot itself prove executing.

Source anchors in the pinned native tree are `packages/plugin/src/promise/plugin.ts`, `promise/event.ts`, `promise/adapter.ts`, `packages/schema/src/event.ts`, `session-event.ts`, and `packages/core/src/tool/plugin/subagent.ts`. Preserve or extend the source-pin audit for the exact fields and ordering assumptions before implementation is accepted. Do not assume `ctx.tool.get`: the verified API uses transform editor get/update and `ctx.tool.list()`.

Public event evidence remains subject to exact native `session.get` verification. Early evidence cannot accept output or replace `execute.after`. Native interrupt/wait/get/context exist, but interrupt's boolean alone is not a termination fence; this work makes no termination claim.

Keep shipping global adapter behavior unchanged for the first closure attempt. The existing adapter continuation path is `.opencode/src/plugin-modules/global-native-plugin.ts` before handling, with protocol checks in `global-protocol.ts` clarification continuation admission. The completed-after path verifies the original child first; continuation uses the exact unresolved task, child, nonce and a fresh call identity. Protocol cancellation returns `termination: "unconfirmed"` without native interruption.

1. Admit a fresh finite read-only task in an isolated evaluation workspace. Complete an authentic native clarification result through the actual adapter after hook, establishing its verified child, parent/agent/cwd, original context and unresolved nonce. Do not fabricate a clarification payload or bypass the native completion checks.
2. Continue precisely that unresolved clarification through the registered supported native path, using the same authorized task/child/nonce and a fresh call identity. Recheck parent/cwd and generation. Existing continuation admission marks running before execution; that state alone is insufficient GN-010 evidence. This is the permitted unresolved clarification exception, never terminal task reuse or a new scope.
3. Establish the continuation’s event-stream boundary before dispatch, then observe fresh public native execution-start/tool/request evidence tied to that exact continuation call and child. A same-child execution.started from an earlier turn, or child ID alone, is insufficient. Record the exact parent/message/call/child mapping and native lookups; source-pin compatibility does not prove the host delivers those events. Reject or classify as inconclusive wrong/stale/duplicate-conflicting/unmatched events, changed parent/cwd/generation, missing observations or disposal. An event from prior clarification execution cannot prove continuation activity. Do not match by nearest session, parent/role alone or elapsed time.
4. Establish an actual pending native operation through a source-only evaluation rendezvous tool registered by the driver through the verified public `ctx.tool.transform` API. The authentic continuation must invoke this declared read-only tool. Its native execute context must match the verified child/session and a fresh invocation after the exact continuation boundary; arm it for only that task/call/generation and reject stale, duplicate or unmatched invocation. The tool reports ready directly to its owning driver and holds its execute Promise pending. Do not depend on streaming stdout, file writes by the child, or the absence of completed callbacks. A registered native tool invocation in that exact child proves activity; its unresolved owned Promise proves the operation is pending at cancellation.
5. After ready, invoke the registered `harness_orchestration` cancellation control with the original exact context and selected version while the rendezvous Promise remains held. Record cancelled state, known verified child ID, JSON-valid raw/text response, and `termination: "unconfirmed"`. Only after cancellation returns may the driver resolve the rendezvous Promise. No production release mechanism or protocol bypass is added. Abort, timeout, invocation error or premature completion makes GN-010 INCONCLUSIVE; always settle owned driver resources without changing protocol retention. Never renew the deadline, accept a gate or release uncertain reservations. Let finite child work finish after rendezvous release, retaining its genuine completed callback. The real `execute.after` stays authoritative: current parent, cwd, generation, exact call and child checks, repeated native lookups around awaited evidence work, and output/metadata/content agreement remain intact. Assert rejection across actual native surfaces, acceptance refusal and retained uncertainty. No event grants output acceptance authority.
6. Dispose only driver resources/subscriptions. Timeout, changed identity, missing event or lack of callback makes the relevant assertion INCONCLUSIVE. It never clears cancelled protocol records, authorizes retirement, restores gates or makes terminal work resumable.

This attempt can establish **GN-010-CONTINUATION** only. The fresh-child subcase **GN-010-FRESH remains NOT_EXERCISED**, because the existing adapter binds fresh children only at completed after. Do not collapse those subcases into universal running-child coverage.

If fresh-child coverage is later required, separately propose early `session.tool.progress` correlation. It must bind the exact admitted parent/message/call, verify child parent/agent/cwd through native lookup, and pair progress with same-child execution-start evidence. Progress occurs before prompt. Reordered execution-start requires a bounded generation-local buffer and finite lifetime, with no deadline renewal; missing, ambiguous, conflicting, stale, duplicate or post-disposal events must fail closed. Repeated native checks at authoritative after cannot be removed. Exact bounds/error policy and all race tests belong in that later approved plan, not this source-driver closure.

## Source-only real-callback evaluation driver

GN-011 needs deterministic delivery timing without a shipped testing bypass. A source-only evaluation driver may proxy the context while registering the single source adapter's actual after callback. When native core invokes that registered callback with a real completed event, hold only the exact selected event **before entering adapter.after and its serialization queue**. Invoke cancellation through the actual registered harness control, then release the original unmodified completed event to that same callback. Both control and after use the adapter's serial queue; holding inside it would deadlock cancellation.

Native core constructs completed events after native execute settles and consumes mutated output/content/metadata after the hook. The driver must use that core-dispatched path. Direct executor calls bypass core before/after unless explicitly routed; hand-created hook events or completion payloads are FIXTURE evidence, never GN-011 LIVE proof. Retain hashes of the held input and released input to establish no driver fabrication or modification. Observe the resulting output/content/metadata and actual native terminal/model/parent-visible content, plus acceptance refusal.

This driver is excluded from installed assets, manifest/package closures and ordinary startup. No installed test switch or second installed adapter is introduced. Use an explicitly selected source evaluation plugin in a separate native instance with a fresh owner-only evaluation root, separate config/data/state/workspace/session and fresh generation/identities. Verify the intended public API and exact native build first; ensure no simultaneously active installed/project adapter, inherited project configuration collision, reused cancellation context, operator database mutation or writes outside the declared evaluation roots. Pin reviewed source/driver hashes and retain nonsecret evidence. The evaluation rendezvous tool is declared in the isolated test scope, performs no child file writes, has a finite timeout and is absent from installed closures. Public registration and native context fields must be covered by the pinned-source audit and verified in the isolated host; missing capability makes the attempt INCONCLUSIVE. No indefinite command or production waiting control is added. Do not enable auth, providers, network, global installation or host activation automatically; those require matching separate authorization.

Each hold is bounded with unconditional release/resource cleanup on timeout or error. A timeout is INCONCLUSIVE and must preserve cancelled protocol records, reservations and acceptance refusal. Driver cleanup cannot retire an uncertain run. No driver-generated event, control result or native result counts as independent acceptance evidence.

A completion already held before cancellation proves actual late delivery/rejection when released, but **cannot prove GN-010**: the native operation already completed. Keep a separate GN-010 attempt that cancels after trustworthy executing evidence and before known completion, or cancel then let the finite child complete naturally for a combined attempt. Record exact ordering and classify an unproved overlap as INCONCLUSIVE, never infer executing from a delayed callback.
