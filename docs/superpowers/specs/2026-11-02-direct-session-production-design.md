# Direct session implementation transport: first production tranche

The owner approved proceeding from the source-only prototype to the first production tranche on the current branch, using fresh implementation and independent review tasks. This document fixes the supported boundary and integration decisions; it does not authorize a live provider run, native activation, network access, credential changes, global installation, or core patches.

## Goal and approaches

Enable an explicit Linux V2 launcher option that routes fresh foreground `implementer/implementation` tasks through public native session operations. A settled, in-scope artifact-proof failure may end that attempt as failed without stopping the whole workflow. Remediation then uses a **new parent dispatch, delegationTaskId, child and prompt**, through existing admission and budgets. One native tool call owns one attempt; there is no hidden retry loop.

Wrapping the existing `subagent` executor is the selected minimal integration. It preserves native before/after hooks and existing parent tool access. A new generic dispatch tool would require another admission surface, while reusing native SubagentJob cannot retract its independent terminal delivery. Neither is included. Other roles/modes and background requests keep the existing guarded native route. Opt-out and V1 retain their existing execution behavior, subject to the new V2 unresolved-direct-attempt barrier.

## Supported trust boundary

- Exactly four existing roles; only fresh foreground `implementer/implementation` uses direct sessions. No clarification, background control, inherited child ID, validator command retry, or implementer/integration direct route.
- Existing scope, task/result contracts, workflow gates, controller budgets and deadlines remain authoritative. Implementation completion does not satisfy validator gates. Workflow budget defaults remain `{"mode":"unbounded"}`; bounded numeric specifications stay bounded.
- Native caller identity is exactly `sessionID`, `agent`, `messageID`, `id`, and the promise `signal`. The before-event tuple, execute caller and after-event tuple must agree; alternate legacy identity aliases are not accepted for this route. Model JSON cannot select a transport, supply a receipt, override identity, extend time, or release capacity.
- The trusted host/plugins and same-UID operator remain inside the existing trust boundary. Public `context({sessionID})` has no allocation/read bound. Local limits are post-read checks. There is no exclusive child lock: reject observed extra prompts, steering, switches and identity ambiguity, and reject tools from terminal children. Do not claim prevention of arbitrary later host/UI activity or hooks owned by other plugins. Raw child transcripts can remain visible in native UI.
- Pending create/prompt/read/interrupt, unknown termination, deadline/cancellation, descope, event loss, unload, malformed results or changed authority retain the reservation and stop admission. An idle observation while a native operation or owned callback is outstanding is insufficient.

## Production components and lifecycle

Create `.opencode/src/plugin-modules/direct-session-transport.ts` as a dependency-free production module. It owns a single-attempt native operation ledger, sealed child/prompt IDs, local context bounds, exact final-turn selection, cancellation/reconciliation and private candidate receipts. It does not create a second controller or validate its own implementation as an independent validator. Keep the TypeScript AST native audit in source-only scripts; audit the actual production projection against committed native schemas, including optionality and variant fields, rather than auditing only the old prototype. Never import the prototype or `typescript` into the production closure or make a generated test import an ungenerated script.

Create `.opencode/src/plugin-modules/direct-session-lease.ts` for a minimal persistent unresolved-attempt barrier. Keep controller integration in `managed-dispatch.ts`, native tool wiring in `v2-native-plugin.ts`, and public API test/audit additions in source tests.

1. **Before hook:** run the existing `admitV2Subagent`/`beforeTask` path first. From the admitted immutable packet, controller attempt and effective foreground mode, select direct only when the option is active and role/mode match. Record the exact native call tuple and post-admission arguments privately. All unsupported calls continue unchanged to the original executor. Deny attempted direct continuation before native launch.
2. **Execute wrapper:** obtain the one-use direct handle for that exact before-event tuple. Recheck the unchanged admitted arguments and caller signal. Require a native primary parent and reassert the original native `subagent` permission through `context.permission.assert({sessionID,agent,source:{type:"tool",messageID,id},action:"subagent",resources:["implementer"],save:["implementer"]})`; replacing execute must not skip the permission assertion located inside the native executor. Persist the lease before calling native create. The original native executor is never called for this attempt. No Job APIs, synthetic messages, fake Job IDs, or fake background acknowledgments occur.
3. **Create and prompt:** allocate the exact child ID before create, so `session.created` can bind only that child and parent; an unrelated child for that parent stops the attempt. Reconcile event and API response identity before prompt. Register the exact own prompt ID/text before calling prompt. Preserve native agent/model selection from the already verified role; deny a direct request containing an explicit model override in this tranche rather than silently ignoring it.
4. **Child execution:** retain the existing tool guards. Track owned child callbacks from the before-hook through after-hook, including pending commands, so a deferred native after-hook cannot disappear from accounting. Any narrowly needed cross-callback launch allowance is an in-memory registry entry for this handle, native parent/call, exact child/prompt and current operation; no generic permission rule, model flag, or global bypass is permitted.
5. **Candidate:** await settled prompt, native wait, get and context; require exact child/parent/agent, successful idle outcome, one exact own user prompt, no unexpected turn activity and a valid completed terminal assistant. Apply 256-message and 1,048,576-byte post-read context bounds, plus existing 32,768-character terminal result bound. Check the controller's fixed deadline after every await. The executor stores the candidate privately and returns only an internal native-schema placeholder: `{output:{sessionID: sealedChildId,status:"completed",output:"Native execution ended; harness validation pending."},content:"",metadata:{}}`. This truthfully describes verified native execution completion, never managed acceptance. It does not call `afterTask`, clear active, publish child result text or mark managed success. Native runtime validates this existing schema before the after-hook; parent publication occurs only after that hook returns.
6. **After hook:** recognize the registered direct invocation before entering the existing native Job/result conversion. Atomically consume its private candidate using a one-use token bound to this after-callback. Require all operations settled, no other owned callbacks or pending commands, matching revision/spec/identity, nonexpired/noncancelled state, and rechecked workspace scope. The token may account for this one final callback, never subtract an arbitrary callback count or accept a boolean from the model. Validate the typed result and actual trace artifacts using the existing managed completion logic. Rewrite output/content/metadata consistently to a wrapper-owned accepted, rejected or stopped result. Clear the direct receipt and lease only after successful terminal bookkeeping; cleanup failure stops and retains evidence. Do not pass this event to native `completedV2Subagent`/`afterTask` again.
7. **Fresh remediation:** only a typed successful implementation result whose ordinary artifact proof is rejected (for example a missing declared artifact or digest mismatch), after all scope/native/callback checks pass, may terminalize the attempt as failed and free its reservation. Recheck scope and deadline again before doing so. Invalid identity, unsafe artifact path/symlink, failed native outcome, missing result, callback ambiguity, cancellation and any other exception stop. Subsequent remediation comes through a separate new call; controller counts and remediation limits apply normally. Retain tombstones for used calls/tasks/children/prompts. A valid non-success or clarification result is unsupported on direct transport in this tranche and stops rather than resuming its child.

The production transport receives a controller-issued admission view with the existing deadline, not the prototype's independent timeout. Keep a bounded 2,000 ms cancellation reconciliation observation window, without treating elapsed time as termination or allowing that window to renew the task deadline.

## Persistence and rollback

The current `dispatch-started.json` only prevents reusing its orchestration ID; `stopped` is in memory. It does **not** stop a fresh orchestration after reload. Add one fixed trace-wide marker at `traceRoot/orchestrations/.direct-session-unresolved.json` inside the excluded generated orchestration coordination area, not the source asset inventory. Verify canonical no-follow trace-root ancestry and owner-controlled parent directories; create parents only under the verified trace root. Create the owner-only marker atomically and exclusively before native create, recording version, orchestration/run ID, canonical workspace/trace roots, spec digest, parent/call/task/child/prompt identities and admitted deadline. These are identifiers, not credentials or raw result text. Existing serial managed activity needs only one lease per trace root, and no-clobber creation arbitrates concurrent setups. Use no-follow checked reads and remove only the exact privately owned file and parent identity. Do not alter the immutable dispatch-started marker or normalized specification.

Every V2 plugin setup, including direct-off, checks this one exact marker path before allowing tools/admission. Use no-follow checks; an unsafe marker fails closed. Marker discovery is O(1) in completed orchestration history: do not enumerate history directories or impose a cumulative history limit on source, portable or external profiles. Install fail-closed guards before reporting an unresolved lease; do not throw before hook registration and expose an unguarded native fallback. Restore a stopped admission state even with no in-memory active task, retain stopped permissions, and permit only diagnosis/isolation already supported by that state. Check again at admission to detect another setup's lease; the currently owned in-memory lease alone is exempt while its exact attempt is active. Malformed or unresolved leases prevent readiness and fresh managed work. A clean terminal after-hook removes only its exact owned trace-wide marker. Lease creation/removal failure is not recoverable success.

This is a restart admission barrier, **not durable direct-session recovery**. A restarted process cannot reconstruct callback accounting or release an old direct lease. Existing recovery may diagnose, but cannot pretend Job evidence resolves a direct attempt. This tranche deliberately retains refusal until a later reviewed native-termination/recovery mechanism can prove release. Do not prescribe manual marker deletion, changed permissions, a fresh trace root, or restart as recovery. In-process uncertainty also retains the marker.

Rollback is omitting the opt-in on a fresh launch **only when no unresolved direct lease exists**, or invoking a prior package only after the same condition has been established. Opt-out must never bypass the lease. An older package cannot recognize the new barrier, so it must not be used while an unresolved lease exists.

## Native output-contract resolution

Committed native source confirms that the original output schema requires a real session ID, `completed|running`, and an output string; it has no `pending` variant. No supported dependency-free union constructor preserving the original validator was established. Keep the original schema and use the private truthful completed-execution placeholder above only after actual verified native termination. `core/src/tool.ts` awaits the after-hook before returning the three channels; `session/runner/step.ts` awaits tool execution before terminal publication. The final after-hook first initializes all channels to a fixed rejection, then performs correlated finalization and writes the final accepted/rejected/stopped result. Catch every direct-branch error and retain stop/lease; do not leak a Promise-hook defect or leave the internal placeholder in a parent-visible return. Earlier trusted plugins can observe the placeholder, as part of the documented host trust boundary. Tests must simulate native output validation and prove no parent publication before final replacement. This resolution avoids a new runtime schema dependency and preserves the native-route validator.
